# Story 2.1: state-endpoints

## Status
Draft

## Story
**As a** user,
**I want** to retrieve the full application state and supported constraints,
**so that** the UI can render the grid and constraint tools accurately.

## Context
This story establishes the read-only state endpoints that the UI depends on.

## Dependencies
- None.

## Acceptance Criteria
1. `GET /api/state` returns full, coherent state in < 200 ms for typical puzzles.
2. `GET /api/constraints` lists all supported types with required payload fields.
3. Responses are stable and backward compatible for the UI.

## Tasks / Subtasks
- [ ] Implement `GET /api/state` endpoint to return AppState (AC: 1, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Ensure response includes grid, candidates, notes, constraints, helpMode, dirty (AC: 1) [Source: docs/architecture.md#AppState]
- [ ] Implement `GET /api/constraints` endpoint to return constraint catalog (AC: 2, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Return type list and required payload fields for each constraint (AC: 2) [Source: docs/architecture.md#Constraint]
- [ ] Add API tests for state/constraints responses and timing constraints (AC: 1, 2, 3) [Source: docs/architecture.md#Tech Stack]
