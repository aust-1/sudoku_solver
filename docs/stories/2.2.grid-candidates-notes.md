# Story 2.2: grid-candidates-notes

## Status
Draft

## Story
**As a** user,
**I want** to update grid values, candidates, and notes via the API,
**so that** the UI can edit puzzles and sync changes reliably.

## Context
This story implements the core write endpoints for grid edits and annotations.

## Dependencies
- Story 2.1 should be completed to ensure read endpoints and AppState are stable.

## Acceptance Criteria
1. Each endpoint updates only the targeted cell data and returns a minimal state delta.
2. Invalid inputs are rejected with clear, consistent errors.
3. Updates remain consistent with server-side solver state.

## Tasks / Subtasks
- [ ] Implement `POST /api/grid/set` for setting cell values (AC: 1, 2, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Return StateDelta updates for grid changes (AC: 1) [Source: docs/architecture.md#StateDelta]
- [ ] Implement `POST /api/candidates/set` for setting candidates (AC: 1, 2, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Return StateDelta updates for candidate changes (AC: 1) [Source: docs/architecture.md#StateDelta]
- [ ] Implement `POST /api/notes/set` for setting notes (AC: 1, 2, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Return StateDelta updates for notes changes (AC: 1) [Source: docs/architecture.md#StateDelta]
- [ ] Add API tests for invalid inputs and delta correctness (AC: 1, 2, 3) [Source: docs/architecture.md#Tech Stack]
