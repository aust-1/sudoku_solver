# Story 1.1: schema-board

## Status
Ready for Dev

## Story
**As a** developer,
**I want** a clearly defined board JSON format with minimal backend validation,
**so that** UI and API stay in sync and imports are reliable.

## Context
This story defines the board schema and validation that other import/export and state APIs rely on.

## Dependencies
- None.

## Acceptance Criteria
1. `board.example.json` is documented with required/optional fields and examples.
2. Backend accepts valid boards and rejects malformed payloads with clear error messages.
3. Validation is fast and does not block normal UI interactions.

## Tasks / Subtasks
- [ ] Review and align BoardFile, Constraint, and CellCoord with architecture data models (AC: 1, 2) [Source: docs/architecture.md#Data Models]
  - [ ] Confirm required/optional fields for BoardFile and Constraint payloads (AC: 1) [Source: docs/architecture.md#BoardFile]
- [ ] Define minimal validation rules for board payloads in the API layer (AC: 2, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Ensure validation supports size, cells map, and constraints list (AC: 2) [Source: docs/architecture.md#BoardFile]
  - [ ] Return clear error responses on invalid payloads (AC: 2) [Source: docs/architecture.md#API Specification]
- [ ] Document `board.example.json` format and examples (AC: 1) [Source: docs/architecture.md#Data Models]
