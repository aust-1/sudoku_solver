# Story 2.3: constraints-crud

## Status
Draft

## Story
**As a** user,
**I want** to add, update, and remove constraints via the API,
**so that** the UI can manage constraint overlays reliably.

## Context
This story implements the constraint CRUD endpoints used by the UI constraint editor.

## Dependencies
- Story 2.1 should be completed to ensure constraint catalog and state are stable.

## Acceptance Criteria
1. New constraints receive unique, stable IDs.
2. Updates modify only the specified payload fields without side effects.
3. Removing a constraint cleans up UI state and related overlays.

## Tasks / Subtasks
- [ ] Implement `POST /api/constraints/add` to add constraints with unique IDs (AC: 1, 3) [Source: docs/architecture.md#API Specification]
  - [ ] Ensure new constraints use `id`, `type`, `payload` structure (AC: 1) [Source: docs/architecture.md#Constraint]
- [ ] Implement `POST /api/constraints/update` to update payload only (AC: 2) [Source: docs/architecture.md#API Specification]
  - [ ] Return StateDelta with updated payloads (AC: 2) [Source: docs/architecture.md#StateDelta]
- [ ] Implement `POST /api/constraints/remove` to remove by ID (AC: 3) [Source: docs/architecture.md#API Specification]
  - [ ] Return StateDelta with removed IDs (AC: 3) [Source: docs/architecture.md#StateDelta]
- [ ] Add API tests for add/update/remove behavior and ID stability (AC: 1, 2, 3) [Source: docs/architecture.md#Tech Stack]
